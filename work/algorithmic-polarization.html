Algorithmic accountability · political polarization

Feed-level auditing

A public-interest baseline for recommendation audits

This concept compares a platform feed with a transparent baseline built from the same user history and candidate content. The difference between the two feeds becomes an object for audit.

01 · Policy problem

Auditing a hidden ranking objective

Recommendation systems make repeated choices about what each person sees. A platform may describe the goals of its system, but an outside researcher cannot usually inspect the full model or reproduce the feed.

Audit challenge

A single post reveals little about a ranking system. The pattern across many recommendations may show whether the system consistently moves a feed toward engagement, similarity, or another objective. Auditors need a clear comparison point for interpreting that pattern.

Design question

Can a transparent reference feed help auditors measure how far a platform’s recommendations move from a stated public-interest baseline?

02 · Proposed method

Parallel feed comparison

The same user history and set of candidate posts enter two recommendation systems. One produces the platform feed. The other produces a public reference feed using a published collaborative-filtering rule.

  1. A

    Platform feed

    The platform’s production system ranks the available posts using its own objective.

  2. B

    Reference feed

    A transparent collaborative-filtering system ranks the same posts using the same user history.

  3. Δ

    Feed difference

    The two ranked lists are projected into a political semantic space. Their distance becomes the proposed Political Bias Score.

03 · Reading the score

Political Bias Score

The score represents the distance between two ranked outputs. It is intended to make a pattern of feed choices measurable and comparable over time.

Possible audit uses

  • Compare the platform feed with the same published baseline over time.
  • Examine whether divergence changes during elections or major political events.
  • Compare results across user histories, regions, and demographic groups.
  • Identify cases that require closer qualitative or legal review.

Required decisions

  • How political position is represented and validated
  • Which candidate posts enter both pipelines
  • How ranked-list distance is calculated
  • What amount of divergence requires action
  • How uncertainty and measurement error are reported

04 · Institutional design

Independent oversight

The concept assigns the reference model and audit process to an independent, multi-stakeholder body rather than to the platform being evaluated.

  • Method: publish the reference algorithm, score calculation, test data requirements, and reporting format.
  • Access: define the user-history and candidate-set data that platforms must provide.
  • Verification: check whether platforms run the comparison as specified.
  • Reporting: publish results, uncertainty, and changes in method.
  • Process: provide a route for correction, challenge, and appeal.

05 · Interpretation

Concept limits

  • The Political Bias Score is a proposed construct and has not yet been validated against polarization outcomes.
  • Collaborative filtering is a design choice, not a neutral or universal definition of the public interest.
  • A difference between feeds does not by itself show harm or unlawful conduct.
  • The baseline could reproduce bias in the user history, candidate set, embeddings, or political labels.
  • The oversight body’s jurisdiction, appointment process, authority, and appeals route require legal design.
